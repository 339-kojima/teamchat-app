# 受け入れ条件・テスト観点

## 受け入れ条件

| Issue | 受け入れ条件 |
|:--|:--|
| アカウント登録・認証 | 表示名・メール・パスワードで登録でき、重複メールと8文字未満の登録を拒否する。正しい認証情報でログインし、ログアウト後は保護画面へ入れない。 |
| チャンネル管理 | 公開／非公開チャンネルを作成でき、作成者は非公開メンバーに含まれる。同一公開範囲で同名は作成できず、作成者のみ編集・削除できる。 |
| プライベートメンバー | 作成者はメンバーを追加・削除できる。追加後は閲覧・投稿でき、除外後は一覧・直接URL・検索から情報を得られない。作成者は外せない。 |
| メッセージ | 閲覧権限のある人が投稿でき、投稿者は自身の投稿をいつでも編集・削除できる。他人の投稿は変更できず、削除跡と投稿者・日時は残る。 |
| スレッド | 親投稿に返信を追加でき、返信件数と返信一覧が一致する。返信に返信できず、削除済み親にも返信を続けられる。 |
| 検索 | ログイン利用者は本文キーワードで検索でき、結果にチャンネル・投稿者・日時が出る。閲覧できない非公開チャンネルの結果は出ない。 |
| 公開API | 認証なしで公開一覧と公開チャンネル投稿を読める。非公開情報と削除済み投稿は返らず、存在しないIDと非公開IDは同じ404となる。 |
| 初期データ | 指定アカウント3件・チャンネル4件・権限が作成され、公開各チャンネルに約10件、非公開にも数件の会話がある。複数返信、3件以上の返信スレッド、編集済み・削除済み投稿が含まれる。 |

## テスト観点

- 認証境界：未ログイン、一般ログイン、作成者、プライベートメンバー、投稿者の組み合わせ。
- 入力境界：空欄、上限値、上限超過、重複メール、同名チャンネル、パスワード不一致。
- 関連データ：親投稿削除後の返信、チャンネル削除時の連鎖削除、メンバー削除後のアクセス。
- 情報漏えい：一覧・検索・直接URL・APIでの非公開名、ID、本文の露出。
- 初期データ：シーダー再実行後も所定のデータと状態になること。
- API：削除済み投稿の除外、404応答の同一性、書き込み系APIが存在しないこと。

## 実装上の前提

MVC構成とし、認可・入力検証・データ永続化を画面表示から分離する。検索の一致方法は Q-08、チャンネル削除確認は Q-05 の回答後に確定する。
